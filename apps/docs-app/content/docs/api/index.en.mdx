# Product API Reference

The Vibe Chat web app composes Better Auth, the product database, Matrix/Synapse, and the standalone Space Runtime through same-origin product APIs. This page documents the browser contracts implemented today. Third-party Space Template submission and Web Push are not yet public.

## Authentication

Product APIs read the Better Auth HttpOnly Cookie session. They do not accept a client-created bearer token. Browser requests should stay same-origin and include cookies:

```ts
const response = await fetch('/v1/product-state', {
  credentials: 'include',
  headers: { accept: 'application/json' },
})
```

Unauthenticated requests return `401 AUTH_SESSION_REQUIRED`. A Matrix access token is returned only by `/v1/session/bootstrap` to the in-memory Matrix client for the current browser. It must not be stored in localStorage, logs, or another product API.

## Product routes

`/spaces` is the authenticated product home. Every item is a running Space Instance with members, the full Chat Core, Kernel state, and an App Project. `/spaces/:spaceId` fixes only the top Kernel Bar; one Space App renders everything below it, including the default or customized Chat UI, and calls the immutable Chat Core through the SDK. During the first migration slice, `:spaceId` may contain the encoded Matrix Room ID used to resolve the same SpaceInstance.

`/messages` and `/rooms/:roomId` are compatibility redirects only. New integrations, callbacks, tests, and links must use the Space routes.

## Current endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/session/bootstrap` | Current product profile and the Matrix device bound to the Better Auth session |
| `GET/PATCH` | `/v1/profile` | Read or update display name, unique username, avatar, and onboarding state |
| `GET` | `/v1/contacts` | Contacts, friend requests, and blocks snapshot |
| `GET` | `/v1/users/search?q=` | Search product users eligible for a friend request |
| `POST` | `/v1/friend-requests` | Send a friend request |
| `POST` | `/v1/friend-requests/:id/accept` | Accept a friend request and establish the Matrix invitation relationship |
| `POST` | `/v1/friend-requests/:id/reject` | Reject a friend request |
| `PATCH` | `/v1/contacts/:userId` | Update the current user's private contact remark |
| `POST/DELETE` | `/v1/blocks`, `/v1/blocks/:userId` | Block or unblock a user |
| `POST` | `/v1/rooms` | Validate members and a fixed Space Template version, then idempotently create one Matrix-backed Space instance |
| `POST` | `/v1/rooms/metadata` | Batch-read product room indexes accessible to the current user |
| `GET/PATCH` | `/v1/product-state` | User notification/theme/locale settings, room preferences, and favorite spaces |
| `PUT` | `/v1/rooms/:roomId/preferences` | Persist the current user's pin/mute state for a real Matrix room |
| `GET` | `/v1/spaces?locale=en` | Read the unified Space Template Market directory with publisher, immutable version, `integrity`, `projectFormat`, and capabilities; only official entries are currently published |
| `PUT` | `/v1/spaces/:spaceId/favorite` | Persist the current account's favorite for a published Space Template |
| `GET` | `/v1/spaces/instances/:roomId` | Read the unified SpaceInstance, Template lineage, Dev/Live pointers, and Agent state after Matrix membership authorization |
| `GET` | `/v1/spaces/instances/:roomId/events` | Subscribe to member, App state, Agent, and build events for the Space |
| `GET` | `/v1/spaces/instances/:roomId/app?channel=dev\|live&version=<readyRevision>` | Load a fixed ready Revision or immutable Live App in an opaque iframe; Runtime non-2xx responses stay intact and never synthesize a Default Chat page |
| `POST` | `/v1/spaces/instances/:roomId/bridge` | Proxy SDK commands allowed by the presence/state/event allowlist |
| `POST` | `/v1/spaces/instances/:roomId/turns` | Submit an explicit `@Agent` request keyed by a Matrix event ID |
| `POST` | `/v1/spaces/instances/:roomId/publish` | Explicitly publish a fixed Dev draft as an immutable Live release |
| `GET` | `/api/credits/status`, `/api/credits/transactions` | Current user's balance and ledger |
| `GET` | `/api/orders`, `/api/subscription/status` | Current user's purchases and entitlement |
| `GET/POST` | `/api/affiliate/*`, `/api/withdrawal/*` | Referral attribution, commissions and KYC-gated withdrawal |
| `POST` | `/api/payment/initiate` | Start an idempotent server-priced checkout |
| `POST` | `/api/chat`, `/api/image-generate`, `/api/video-generate` | Billable AI generation with failure refunds |
| `POST` | `/api/upload` | Authenticated image upload with type and size limits |

Payment success/cancel pages are presentation only. Payment fulfillment comes from verified provider callbacks. AI task and ledger endpoints are owner-scoped; request IDs must be stable across a retry.

## Product state example

```json
{
  "preferences": {
    "notificationsEnabled": true,
    "theme": "system",
    "locale": "en"
  },
  "roomPreferences": [
    {
      "matrixRoomId": "!room:example.org",
      "pinned": true,
      "muted": false
    }
  ],
  "favoriteSpaceIds": ["space-campfire"]
}
```

Space Template Market entries use the common `vibechat.space-template-market-entry/v1` shape:

```json
{
  "schemaVersion": "vibechat.space-template-market-entry/v1",
  "id": "space-campfire",
  "versionId": "tplv-space-campfire-0-1-0",
  "semanticVersion": "0.1.0",
  "artifact": {
    "schemaVersion": "vibechat.space-template-artifact/v1",
    "id": "tpla-<source-sha256>",
    "format": "agentos-app-v1",
    "sourceHash": "sha256:<source-sha256>"
  },
  "projectFormat": "agentos-app-v1",
  "publisher": {
    "id": "publisher-vibechat",
    "displayName": "VibeChat",
    "verification": "official"
  },
  "provenance": {
    "origin": "repository",
    "publisherId": "publisher-vibechat",
    "sourcePath": "packages/space-templates/official/space-campfire/app"
  }
}
```

Official and user Templates do not use different data types. The official mark comes from `publisher.verification`; repository sources use `provenance.origin=repository`, while a future user publication from a Space App uses the same fields with `origin=app`. User submission APIs, review, and production storage are not open yet. A Template artifact contains the complete multi-file App Project under normalized, hashed paths. Applying it copies that tree into the Space's independent Project, where later Agent revisions may split or add source modules without mutating the Market version.

## Error shape

Product APIs use a stable error shape. The response header and body carry the same request ID:

```json
{
  "error": {
    "code": "PRODUCT_ROOM_NOT_FOUND",
    "message": "PRODUCT_ROOM_NOT_FOUND",
    "details": {},
    "requestId": "request-id"
  }
}
```

Clients must handle the HTTP status and `error.code`. A service failure must never create a fake local user, room, or mutation.

## Data authorities

- Better Auth: accounts and browser sessions.
- Product database: profiles, social relationships, room indexes, user preferences, room preferences, and space favorites.
- Matrix/Synapse: room membership, timelines, relation events, typing, read receipts, presence, and media URIs.
- Browser: only Matrix SDK IndexedDB sync/timeline cache and non-authoritative theme cache.

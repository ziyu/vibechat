# 产品 API 参考

Vibe Chat Web 应用通过同源产品 API 组合 Better Auth、产品数据库、Matrix/Synapse 和独立 Space Runtime。这里记录当前已经实现的浏览器契约；第三方 Space Template 上架和 Web Push 尚未开放。

## 身份验证

产品 API 读取 Better Auth 的 HttpOnly Cookie session，不接受客户端自建 Bearer token。浏览器请求应保持同源并携带 Cookie：

```ts
const response = await fetch('/v1/product-state', {
  credentials: 'include',
  headers: { accept: 'application/json' },
})
```

未登录时返回 `401 AUTH_SESSION_REQUIRED`。Matrix access token 只由 `/v1/session/bootstrap` 返回给当前浏览器内存中的 Matrix client，不应写入 localStorage、日志或其他产品 API。

## 产品路由

`/spaces` 是登录后的产品首页。列表中的每一项都是一个运行中的 Space Instance，拥有成员、完整 Chat Core、Kernel 状态和 App Project。`/spaces/:spaceId` 只固定顶部 Kernel Bar，其下由单一 Space App 渲染，包括默认或定制后的 Chat UI；App 通过 SDK 调用不可修改的 Chat Core。首个迁移切片允许 `:spaceId` 暂时携带用于解析同一 SpaceInstance 的编码 Matrix Room ID。

`/messages` 与 `/rooms/:roomId` 只保留兼容重定向。新的集成、回跳、测试和链接必须使用 Space 路由。

## 当前端点

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/v1/session/bootstrap` | 当前产品资料与当前 Better Auth session 对应的 Matrix device bootstrap |
| `GET/PATCH` | `/v1/profile` | 读取或更新昵称、唯一用户名、头像与 onboarding 状态 |
| `GET` | `/v1/contacts` | 联系人、好友请求与屏蔽快照 |
| `GET` | `/v1/users/search?q=` | 搜索可发起好友请求的产品用户 |
| `POST` | `/v1/friend-requests` | 发起好友请求 |
| `POST` | `/v1/friend-requests/:id/accept` | 接受好友请求并确认 Matrix 邀请关系 |
| `POST` | `/v1/friend-requests/:id/reject` | 拒绝好友请求 |
| `PATCH` | `/v1/contacts/:userId` | 更新当前用户私有的联系人备注 |
| `POST/DELETE` | `/v1/blocks`、`/v1/blocks/:userId` | 屏蔽或解除屏蔽 |
| `POST` | `/v1/rooms` | 校验成员和固定 Space Template 版本后幂等创建统一 Matrix Space 实例 |
| `POST` | `/v1/rooms/metadata` | 批量查询当前用户可访问的产品 room index |
| `GET/PATCH` | `/v1/product-state` | 用户通知、主题、语言、房间偏好与空间收藏快照 |
| `PUT` | `/v1/rooms/:roomId/preferences` | 保存当前用户对真实 Matrix 房间的置顶/静音状态 |
| `GET` | `/v1/spaces?locale=zh-CN` | 获取统一 Space Template 市场目录、Publisher、不可变版本、`integrity`、`projectFormat` 与能力信息；当前只发布官方条目 |
| `PUT` | `/v1/spaces/:spaceId/favorite` | 保存当前账号的已发布 Space Template 收藏 |
| `GET` | `/v1/spaces/instances/:roomId` | 按 Matrix membership 读取统一 SpaceInstance、Template lineage、Dev/Live 与 Agent 状态 |
| `GET` | `/v1/spaces/instances/:roomId/events` | 订阅当前 Space 的成员、App state、Agent 和构建事件 |
| `GET` | `/v1/spaces/instances/:roomId/app?channel=dev\|live&version=<readyRevision>` | 在 opaque iframe 中加载固定 ready Revision 或不可变 Live App；Runtime 非 2xx 保持原始状态，不合成 Default Chat 页面 |
| `GET` | `/v1/rooms/:roomId/revisions` | 为当前 Matrix 成员读取最多 50 条不可变 Revision 摘要；响应不返回源码或 Object Store key |
| `POST` | `/v1/spaces/instances/:roomId/bridge` | 代理通过 SDK allowlist 校验的 App presence/state/event 命令 |
| `POST` | `/v1/spaces/instances/:roomId/turns` | 提交带 Matrix event ID 和结构化 Agent Mention 的显式请求；Backend 会复读事件并核验 sender/target 后再计费入队 |
| `POST` | `/v1/spaces/instances/:roomId/publish` | 将固定 Dev draft 显式发布为不可变 Live release |
| `POST` | `/v1/spaces/instances/:roomId/restore` | 由可信 Kernel 从官方 Default Chat artifact 或不可变历史 Revision 恢复当前 Space；请求固定幂等 ID 与预期 ready Revision，重新构建隔离 Candidate，且不改变已发布 Release、Matrix timeline、成员或 App State |
| `GET` | `/api/credits/status`、`/api/credits/transactions` | 当前用户积分余额与账本 |
| `GET` | `/api/orders`、`/api/subscription/status` | 当前用户订单与权益 |
| `GET/POST` | `/api/affiliate/*`、`/api/withdrawal/*` | 推荐归因、佣金与 KYC 提现 |
| `POST` | `/api/payment/initiate` | 按服务端价格发起幂等结账 |
| `POST` | `/api/chat`、`/api/image-generate`、`/api/video-generate` | 带失败退款的 AI 生成 |
| `POST` | `/api/upload` | 校验类型和大小的登录态图片上传 |

支付成功/取消页只负责展示，履约权威来自验签后的 provider 回调。AI 任务和账本接口绑定当前用户，重试同一操作必须复用稳定 request ID。新账号默认通过幂等账本交易获得 1000 个欢迎积分，可直接在 Space 中与 Agent 对话；部署方可用 `CREDITS_NEW_USER_GRANT` 调整或关闭。Agent 请求先预留积分，完成后按 Runtime 返回的真实 token usage 结算，失败使用稳定交易 ID 退款。

Revision 历史从数据库 migration `0018` 记录的当前 ready Revision 开始；在此基线前已经失去 Product DB pointer 的对象不会被推断恢复。恢复历史 Revision 不调用 Agent，也不消耗 AI credits。Runtime 会重新读取内容寻址源码，校验对象与 Project hash，并且只在隔离 Candidate ready、预期 ready 并发屏障仍匹配时移动当前指针。

## 产品状态示例

```json
{
  "preferences": {
    "notificationsEnabled": true,
    "theme": "system",
    "locale": "zh-CN"
  },
  "roomPreferences": [
    {
      "matrixRoomId": "!room:example.org",
      "pinned": true,
      "muted": false
    }
  ],
  "favoriteSpaceIds": ["space-campfire"]
}
```

Space Template 市场条目使用 `vibechat.space-template-market-entry/v1` 统一结构：

```json
{
  "schemaVersion": "vibechat.space-template-market-entry/v1",
  "id": "space-campfire",
  "versionId": "tplv-space-campfire-0-1-2",
  "semanticVersion": "0.1.2",
  "artifact": {
    "schemaVersion": "vibechat.space-template-artifact/v1",
    "id": "tpla-<source-sha256>",
    "format": "agentos-app-v1",
    "sourceHash": "sha256:<source-sha256>"
  },
  "projectFormat": "agentos-app-v1",
  "publisher": {
    "id": "publisher-vibechat",
    "displayName": "VibeChat",
    "verification": "official"
  },
  "provenance": {
    "origin": "repository",
    "publisherId": "publisher-vibechat",
    "sourcePath": "packages/space-templates/official/space-campfire/app"
  }
}
```

官方和用户 Template 不再使用不同数据类型：官方标记来自 `publisher.verification`，仓库来源使用 `provenance.origin=repository`；未来用户从 Space App 发布的版本使用相同字段和 `origin=app`。当前用户上架 API、审核和生产存储尚未开放。模板 artifact 包含按路径规范化和 hash 校验的完整多文件 App Project；模板被应用后，源码复制为该 Space 的独立 Project，后续 Agent 可拆分或新增源码模块，Revision 不修改市场版本。

## 错误结构

产品 API 使用稳定错误结构，并在响应头和正文中返回相同的请求 ID：

```json
{
  "error": {
    "code": "PRODUCT_ROOM_NOT_FOUND",
    "message": "PRODUCT_ROOM_NOT_FOUND",
    "details": {},
    "requestId": "request-id"
  }
}
```

客户端必须根据 HTTP 状态和 `error.code` 处理失败，不能在服务失败时创建本地假用户、假房间或假 mutation。

## 数据权威

- Better Auth：账号与浏览器 session。
- 产品数据库：profile、社交关系、room index、用户偏好、房间偏好和空间收藏。
- Matrix/Synapse：房间 membership、timeline、关系事件、typing、read receipt、presence 和媒体 URI。
- 浏览器：仅保留 Matrix SDK 允许的 IndexedDB sync/timeline 缓存与非权威主题缓存。

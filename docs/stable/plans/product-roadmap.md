# Vibe Chat 产品路线图

> 生命周期：长期稳定
> 文档类型：计划
> 状态：生效
> 更新日期：2026-08-11
> 维护范围：产品与工程阶段顺序

路线图表达当前认可的交付顺序，不承诺未经评审的具体日期。详细产品边界以[VibeChat MVP 版本产品与技术设计](../designs/vibechat-mvp-product-and-technical-design.md)为准。

## P0：工程与文档基线

- 单一 TanStack Start 产品应用和独立文档站可重复构建。
- 共享库、配置、i18n、权限和测试约束明确。
- 仓库文档按开发中、长期稳定、已归档管理，并按设计、Runbook、参考资料、发布说明和计划分型。

完成标准：`pnpm docs:check`、`pnpm typecheck`、`pnpm build`、`pnpm build:docs` 通过。

## P1：前端产品骨架验收

- 完成消息、联系人、发现、我的四项主导航骨架。
- 建立房间、会话列表和氛围空间画布的基础信息架构。
- 验证 Web/PWA、响应式、i18n、主题和无障碍基础。

完成标准：关键页面浏览器走查和对应 TanStack E2E 通过。

## P2：产品后端决策与最小闭环

- 评审产品后端、数据库、认证和 Matrix/Synapse 接入方案。
- 固化身份映射、session/device 生命周期和消息同步边界。
- 建立可观测性、备份、迁移与回滚方案。

本阶段开始前不得把现有 SaaS 脚手架能力自动视为最终产品决策。

## P3：氛围空间运行时

- 实现 manifest、capability、host bridge 和安全沙箱。
- 实现 iframe 外控制岛、恢复视图和敏感操作确认。
- 提供 CLI、SDK、模拟宿主和示例空间。

## P4：发现、发布与治理

- 建立氛围空间发现、版本固定、审核、撤销和迁移流程。
- 完成开发者令牌、发布渠道和可观测性。
- 依据稳定协议补齐公开开发者文档。

## 后续独立项目

E2EE、原生客户端、音视频、无代码搭建器、商业化分成、公共房间和社区治理均需独立设计评审，不纳入上述阶段的默认范围。

## 优先级 P0：会影响当前开发判断

- 审计 `libs/*/AGENTS.md` 中对已移除 Next.js、Nuxt.js 产品应用的描述，保留真正的框架无关约束，删除不存在的集成入口。
- 审计 `libs/*/README*.md` 中指向 `apps/next-app`、`apps/nuxt-app` 的示例，并为 TanStack Start 补齐当前代码入口。
- 审计 `tests/e2e/TEST-CATALOG.md` 中当前用例与历史结果的边界，避免把旧多端测试结果当作现行验收范围。

## 优先级 P1：发布内容一致性

- 按稳定设计重写 `apps/docs-app/content/docs/` 的产品介绍和快速开始。
- 明确文档站中的 API 内容是用户参考还是占位页，删除无法兑现的“完整 API”承诺。
- 建立中英文内容同步检查，确保同主题的 `*.en.mdx` 与 `*.zh-CN.mdx` 成对维护。

## 优先级 P2：结构与质量自动化

- 为包级 README 增加维护状态或最后核验日期。
- 在 CI 中运行 `pnpm docs:check`。
- 评估 Markdown 格式、术语和中英文配对检查，不在没有明确规则前引入大规模自动重写。

## 完成条件

- 非归档文档不再把已移除的产品应用描述为当前支持范围。
- 所有包级入口都指向存在的代码或明确标注的历史资料。
- 文档站公开内容与稳定设计的产品术语、范围和启动方式一致。
- 完成后将有效规则写入治理文档，并归档本清单。
